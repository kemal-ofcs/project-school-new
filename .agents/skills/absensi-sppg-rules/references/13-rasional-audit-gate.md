# Rasional audit gate (ui-guard, a11y, page-guard, dialog, route-guard, list-bound, sql)

Dipindahkan APA ADANYA dari `CLAUDE.md` (2026-10-15). Isinya tidak diubah; hanya lokasinya.

- `audit:ui-guard` enforces rule 5 mechanically: every `page.tsx` in either workspace that `await`s a function imported from `@/lib/gateways/*` whose name begins with a mutating verb must guard it with `isSubmittingRef`. Before it existed the rule lived only in whoever's memory was writing the code, and the first run found 14 of 25 mutating pages unguarded — payroll runs, settings, operator deletion among them. Three properties make it real and must survive: it counts only functions actually imported from a gateway module (a name-only match flags `createQrPng`, which draws a PNG on a canvas, and an audit that accuses correct code gets switched off); it checks that each *handler* touches `isSubmittingRef.current`, not merely that the file mentions it somewhere (a page can declare the ref and never use it — `karyawan/page.tsx` did exactly that); and it rejects a ref declared *after* an early return, because a hook skipped on some renders changes hook order and takes the whole page down. It has no exemption list and must never grow one.

- `audit:a11y` names every form control. A `<select>` with no label is announced by a screen reader as nothing but its current value — "Semua Divisi" — with no hint that it filters division rather than status or sort order; the attendance-history page has three such selects side by side. `placeholder` is not a label: it is announced inconsistently and vanishes the moment the user starts typing. The gate accepts all three valid forms — `htmlFor`/`id` pairing, `aria-label`/`aria-labelledby`, and a wrapping `<label>` — because a check that counts only `htmlFor` would accuse hundreds of correct controls, and an audit that accuses correct code gets switched off. That lesson came from this audit itself: the first grep reported 26 unlabeled controls on the attendance-correction page, when every one of them already carried an `aria-label` that simply sat on the next line. Labels must name the control's FUNCTION, never its selected value — "Filter divisi", not "Semua Divisi".

- `audit:page-guard` requires authorization, not just authentication. Its scope is self-declaring, with no exemption list: a file claims to be private by redirecting unauthenticated users to `/login`, and only counts if it also loads domain data through a gateway — so login, forbidden, and lupa-password fall outside by their own nature. It demands a permission check *with a navigation consequence*, which is exactly the distinction that let the gap through: `payroll/page.tsx` already called `hasPermission`, but only to enable buttons while the salary data loaded regardless. Three guard forms are accepted because all three are in use and all three are valid — `canAccessArea` + `redirect`, a `hasPermission` branch that pushes elsewhere, and `operators/page.tsx`'s stricter `isSuperadmin` check. Two refinements were forced by false results and must survive: the predicate has to sit inside an actual `if (…)` condition whose branch navigates, because merely finding it *near* a navigation passed `mobile/settings` on the strength of `user?.isSuperadmin` appearing in a `useEffect` dependency array seven lines above the logout button's `router.replace`; and a page checking **three or more distinct areas** is classified a navigation hub, whose per-card checks are its authorization. That second rule is not a convenience — Mobile's Settings hub maps to `branding.manage`, which is absent from both the operator and scanner default bundles, so a blanket guard there would strand those roles with no route to 2FA, password recovery, or even logout, that page being the only way to reach them on Mobile.

- `audit:dialog` requires every modal surface to be a `<Modal>` or a native `<dialog>`. Seventeen hand-rolled overlays once lived across nine files — a `<div>` with `fixed inset-0`, no `role="dialog"`, no `aria-modal`, no Escape, no focus entry or restoration, no Tab trap. To a screen reader those were not dialogs at all, merely boxes that appeared while everything behind them stayed reachable. The shared `<Modal>` inherits all of it at once, so one fix to the component lands on every page; `<dialog>` is accepted too because it carries semantics and Escape natively, and `mobile/foto-absensi` legitimately uses it. Focus, scroll lock, and the Tab trap are spelled once in `useDialogFocus` (`lib/hooks`, which **is** synced) rather than copied into both Modal components — Mobile's Modal previously managed no focus at all, leaving focus on the trigger button behind the backdrop.

- `audit:route-guard` requires every route handler exporting `POST`/`PUT`/`PATCH`/`DELETE` to restrict the request origin. This matters more here than in a typical app: because static export forbids `GET` handlers, *every* endpoint is a POST, so the method no longer tells you which ones change state — an explicit check is the only remaining boundary. Both forms count, and both are correct: `assertSameOriginMutation(request)` throws, while `auth/session` uses the boolean `isSameOriginMutation(request)` so it can shape its own JSON reply. The gate requires an actual **call**, not just the identifier, because a file whose call was deleted but whose import remained would otherwise pass. No Rust client calls these route handlers anymore: Desktop and Mobile talk only to the database (see "Application-server path retired" below), so guarding a route cannot break a device.

- `audit:list-bound` requires a bound on every query over a table that grows with each operating day. The criterion is deliberately not "big table": it is whether rows accumulate every operating day with nothing pruning them. `master_data` holds 800 people and that is a lot, but the institution bounds it; `absensi_harian` is bounded by nothing but time. Flagging a shift list or a holiday list would only get the gate switched off. Its first run found two real defects — `getRekapHarian`, whose filter type had no `limit` at all so *no caller could bound it* (±24.000 rows for 800 personnel over one month, all rendered into one table), and `listTeachingJournals`, where every filter is optional so an unfiltered call returns every journal ever recorded. Four properties keep it honest and must survive: **the unit is one query, not one function** — Rust's `dashboard_data` is a single function whose "top" branch has a `LIMIT` and whose "daily" branch does not, so checking per function lets the first excuse the second; **folding stops at the variable's next re-declaration** — queries are assembled at runtime (`query += …`, `query.push_str(…)`), and without that boundary `getRekapHarian` absorbs the `GROUP BY` belonging to `getRekapBulanan` further down the same file, both using the name `query`; **an equality pin only counts when the same query has no range branch**, because a function carrying both `tanggal = ?` and `>= ? AND <= ?` is unbounded on the second; and **plain double-quoted SQL is scanned, not just template literals**, since `snapshot.ts` writes part of its queries as ordinary strings and reading only backticks hid sixteen queries in silence. Two markers may be written *inside a query*, never in a separate list: `-- batas: …` for a query bounded for reasons its SQL cannot show, and `-- sengaja-utuh: …` for one that must NOT be bounded. The sync snapshot is the second kind — truncating it makes a device pull incomplete data and believe it complete — and every query using that marker is counted and printed on every run, so the decision stays visible instead of becoming an invisible exemption.

- `audit:sql` executes the SQL instead of reading it: it builds the schema through the same `scripts/lib/cloud-schema.ts` path `audit:schema` uses, then asks SQLite to `prepare` every SQL literal in both Rust and TypeScript. It exists because Fase 4 shipped nine references to columns that never existed (`m.jabatan`, `m.nama_lengkap`, `pmd.status_kehadiran`) through a fully green quality gate — lint, typecheck, schema audit and contract audit all inspect the *shape* of the code, so a mistyped column is merely text inside a string to every one of them. Two properties keep it honest and must survive: it never parses DDL itself (a second parser would become the very drift it exists to catch), and queries it cannot reconstruct — those built from runtime interpolation — are **counted and listed**, never dropped in silence. An audit that hides its own coverage decays into a false pass, exactly as the old `schema-audit.ts` did when it reported "100% KONSISTEN" while checking zero tables. Rust queries assembled from local variables fall in that uncovered set on purpose; they are covered instead by tests that `prepare` them against a schema built from `storage::initialize`, which is the stronger form and the one to prefer for new Rust SQL.
