# Deploy Web (Docker, paket Windows) dan lisensi offline

Dipindahkan APA ADANYA dari `CLAUDE.md` (2026-10-15). Isinya tidak diubah; hanya lokasinya.

**Web self-hosted diserahkan sebagai image, bukan repo.** `web-desktop/Dockerfile` membangun keluaran `standalone` (aktif hanya bila `KOS_BUILD_STANDALONE=1`, karena `next start` tidak melayaninya dan Vercel tidak memerlukannya) dan hasilnya tidak memuat `src/`, `node_modules` lengkap, maupun source map. Dua hal di jalur ini berbentuk "build tetap hijau" dan wajib dijaga: (1) Next.js MENYALIN setiap `.env*` ke `.next/standalone/`, sehingga tanpa `web-desktop/.dockerignore` dan langkah pemeriksaan di Dockerfile, alamat dan token database milik pengembang ikut terkirim ke setiap pembeli; langkah itu menghapus lalu MEMVERIFIKASI dan menggagalkan build bila masih ada `.env*`, `.ts`, `.tsx`, `.rs`, atau `.map`. (2) Cookie sesi bertanda `Secure` di production dan browser hanya mengizinkan kamera pada HTTPS, jadi paket pembeli di `deploy/` selalu menaruh Caddy di depan aplikasi (`KOS_TLS=internal` untuk LAN); membuka aplikasi lewat HTTP polos membuat login gagal tanpa pesan. Port database di `deploy/docker-compose.yml` sengaja TIDAK dibuka: `sqld` tanpa autentikasi yang terbuka ke LAN bisa dibaca dan diubah siapa pun, melewati login, RBAC, dan lisensi. Nama layanan Docker (`http://database:8080`) tidak dikenali `reviewDatabaseEndpoint` sebagai jaringan privat, sehingga compose itu menyetel `KOS_ALLOW_INSECURE_DATABASE=1`; compose lama di root repo tidak menyetelnya dan karena itu tidak pernah bisa jalan. Variabel server memakai nama `KOS_DATABASE_URL`/`KOS_DATABASE_AUTH_TOKEN`/`KOS_DATABASE_PROVIDER`/`KOS_ALLOW_INSECURE_DATABASE`/`KOS_TRUSTED_PROXY_HOPS`, dengan nama `TURSO_*`/`SPPG_*` sebagai alias yang kalah bila keduanya diisi.

**Paket Windows tanpa Docker (`bun run paket:build`).** Hasil build `standalone` yang sama dibungkus bersama `node.exe`, `caddy.exe`, dan peluncur `deploy/windows/mulai.mjs`, yang menjalankan aplikasi admin, situs publik, dan Caddy lalu menghidupkan kembali yang mati. `deploy/Caddyfile` dipakai KEDUA paket: tujuan proxy dan nama sertifikatnya dibaca dari environment (`KOS_WEB_UPSTREAM`, `KOS_PUBLIC_UPSTREAM`, `KOS_SITE_HOST`) dengan bawaan milik Docker, jadi mengubahnya berarti menguji dua jalur. Lima hal wajib dijaga. (1) `sqld` tidak punya versi Windows, sehingga bawaan paket ini adalah berkas SQLite lewat `KOS_DATABASE_URL=file:...`. Itu jalur Web-saja: provider `local_file` tetap ditolak di Web, dan Desktop/Mobile tidak bisa terhubung ke berkas itu. Sekolah yang juga memakai Desktop/Mobile mengisi alamat server database. (2) Berkas itu ditulis DUA proses (admin dan situs publik), sedangkan bawaan klien libSQL adalah langsung gagal "database is locked". `fileDatabaseOptions` (`database-config.ts`, ikut tersalin ke `web-public`) memberi waktu tunggu 5 detik dan `db.ts` menyalakan WAL; `file-database.test.ts` membuktikannya dengan proses kedua yang sungguhan, karena di dalam satu proses kuncinya tidak bisa diuji. (3) Build berjalan di folder kerja pengembang, tempat `.env` berisi token sungguhan, dan di sini tidak ada `.dockerignore`. `build-paket.ts` mengosongkan setiap kunci `.env` itu selama build, membuang lalu MEMERIKSA `.env*`/`.ts`/`.tsx`/`.rs`/`.map`, dan menyisir seluruh paket terhadap NILAI rahasia dari ketiga `.env` pengembang; satu temuan menggagalkan build. (4) Kedua aplikasi hanya mendengarkan di `127.0.0.1`; pintu dari jaringan hanya Caddy. Mengubah `HOSTNAME` di peluncur membuka aplikasi lewat HTTP polos, tempat login gagal tanpa pesan. (5) Di Windows, port yang sudah dipakai TIDAK menghasilkan galat: Caddy berhasil mendengarkan di port 443 milik Apache (Aplikasi Dapodik memasangnya di komputer operator sekolah), log-nya bersih, dan alamat admin menampilkan halaman "Forbidden" milik program itu. Karena itu `mulai.mjs` memeriksa setiap port dengan MENYAMBUNG ke sana sebelum menyalakan apa pun (`portTerpakai`); mencoba mendengarkan tidak mendeteksinya. Port 80 yang terpakai bukan kegagalan: peluncur mengisi `KOS_AUTO_HTTPS` supaya Caddy tidak membuat pengalih `http://`. Pengalih port 80 itu hanya menolong alamat TANPA port, sedangkan Dapodik memaksa alamat berport; karena itu `deploy/Caddyfile` memasang `listener_wrappers { http_redirect; tls }`, sehingga `http://alamat:port` dialihkan ke `https://` alih-alih ditolak dengan "client sent an HTTP request to an HTTPS server". Urutannya wajib `http_redirect` sebelum `tls`. `admin off` di berkas yang sama juga wajib bertahan: antarmuka administrasi Caddy memakai `127.0.0.1:2019`, dan Caddy lain di komputer yang sama (pemasangan aplikasi Absensi Perusahaan, misalnya) membuat proxy ini gagal menyala berulang-ulang. Peluncur yang dijalankan Task Scheduler berjalan sebagai SYSTEM, jadi `process.kill(pid, 0)` dari akun biasa menjawab EPERM, dan itu berarti proses HIDUP.

**Lisensi offline Ed25519 (Desktop, Mobile, dan Web self-hosted).** Build Tauri menolak login tanpa lisensi yang ditandatangani pemilik aplikasi. Penerbitnya SENGAJA di luar repo ini — folder `lisensi` milik pemilik aplikasi (CLI Bun, lintas produk, private key terenkripsi passphrase); aplikasi hanya memegang public key di `PRODUCT_PUBLIC_KEY_HEX` (`desktop/license.rs`, tersalin ke Mobile), dan selama konstanta itu masih nol SETIAP lisensi ditolak. Format `LIS1.<payload b64url>.<sig b64url>`; tanda tangan dihitung atas byte `LIS1.<payload>` apa adanya sehingga JSON tidak pernah disusun ulang. Aturan validasi isinya dieja dua kali — `validasiLisensi` (TS, di alat penerbit) dan `validate_payload` (Rust) — dan diuji dengan vektor kembar yang sama; mengubah satu sisi tanpa sisi lain membuat lisensi yang sah ditolak di lapangan. Lisensi disimpan di kunci `app_license` tabel `setting_gex_system` (ikut sinkronisasi, lewat rute kanonik `setting/update`), jadi cukup dipasang SEKALI per lembaga; kunci itu TIDAK boleh masuk `DEVICE_LOCAL_SETTING_KEYS`. Tiga status memblokir login (`missing`, `invalid`, `device_not_listed`) dan gerbangnya ada di awal `desktop_login` — satu kali untuk jalur online dan offline. Jenis lisensi hanya dua, `beli_putus` dan `sewa`; sewa diterbitkan dengan `--hari N` (hari terbit ikut dihitung) dan `LicenseStatus.days_left` memakai hitungan yang sama, sehingga hari terakhir = 1. Teks lisensi dibersihkan dari SEMUA spasi/baris baru sebelum diperiksa (`compact_license_text` ↔ `rapikanTeks`). Pemasangan baru meminta lisensi SEBELUM provisioning: lisensi disimpan lokal saja (belum ada tujuan sync), lalu dibawa ke cloud oleh bootstrap Superadmin (`bootstrap_license_text`) atau oleh "gabung ke database yang sudah ada" (`publish_local_if_cloud_missing`, dijalankan SEBELUM pull pertama karena pull menimpa setting lokal; lisensi yang sudah ada di database tidak pernah ditimpa). Kartu Lisensi (termasuk sisa sewa) hanya untuk Superadmin. Dua status mengizinkan login dalam **mode baca-saja**: `berlaku_sampai` lewat (sewa habis) dan `SPPG_BUILD_DATE` (ditulis `build.rs`) lebih baru dari `pembaruan_sampai` — versi lama tetap berfungsi penuh selamanya, versi baru butuh paket pembaruan. Mode baca-saja ditegakkan di SATU tempat, `require_any_permission` (`require_permission` memanggilnya, dan `payroll/commands.rs` kini memakai gerbang yang sama alih-alih salinan sendiri): hanya izin `*.view`, `sync.retry`, dan `database_backup.export` yang lolos, karena data yang tertahan di outbox harus tetap sampai ke cloud dan datanya milik klien. Tanggal berakhir dibandingkan di setiap gerbang, bukan hanya saat login — terminal pemindai bisa login berbulan-bulan. Kode perangkat = hash SHA-256 MachineGuid (Windows) / machine-id (Linux) / id acak aplikasi (Android, iOS, macOS), jadi instal ulang Windows atau hapus data aplikasi Android menghasilkan kode baru. Di samping kodenya, layar aktivasi dan kartu Lisensi menampilkan NAMA perangkat (`device_name`: `COMPUTERNAME` di Windows, merek + model lewat `getprop` di Android) supaya penerbit tahu kode mana milik PC atau HP yang mana; nama itu hanya untuk dibaca dan tidak pernah diikat lisensi. HP hanya wajib terdaftar bila lisensinya `kunci_mobile: true`. Web menegakkan lisensi HANYA pada build self-hosted (lihat paragraf berikutnya); pada deployment milik pemilik aplikasi `lib/gateways/license.ts` menerima `null` dari server dan seluruh UI lisensi (`components/license/*`, disalin ke Mobile lewat `filesToCopy`) tidak merender apa pun. Pemasangan tanpa sesi hanya diizinkan bila lisensi saat ini tidak aktif penuh; mengganti lisensi yang masih aktif menuntut Superadmin, dan lisensi yang tidak aktif penuh untuk perangkat pemasangnya ditolak supaya tidak ada yang mengunci dirinya sendiri keluar.

**Lisensi versi Web: lisensi yang sama, identitas yang berbeda.** Server Web self-hosted memakai teks `app_license` yang sama, diperiksa oleh `src/lib/server/license.ts`, cermin `license.rs`. Format dan aturan isinya kini dieja TIGA kali (alat penerbit `format.ts`, `license.rs`, `server/license.ts`) dan diuji dengan vektor yang sama, `VEKTOR_V1`..`V3` plus daftar aturan versi Web; mengubah satu tanpa dua lainnya membuat lisensi yang sah ditolak di lapangan. Dua kolom OPSIONAL baru membawa cakupan Web: `instance_web` (kode berawalan `S`) dan `website` (1-10 FQDN). Keduanya hanya ditulis bila diisi, sehingga lisensi dan vektor lama tidak berubah satu byte pun, dan Rust WAJIB mengenalnya walau tidak menegakkannya: lisensi itu tiba di Desktop/Mobile lewat sync, dan kolom asing ditolak sebagai lisensi tidak sah. Kode `S` SENGAJA bukan anggota `is_device_code`: bila ia masuk daftar `perangkat`, daftar itu tidak lagi kosong dan semua Desktop ikut wajib terdaftar. Yang diikat di Web adalah DATABASE, bukan mesin (kontainer bisa dibuat ulang kapan saja): id acak di kunci `web_instance_id` tabel `setting_gex_system`, lahir sekali pada pembacaan pertama, di-hash dengan rumus `device_code` yang sama. Kunci itu ikut sinkronisasi dan tidak berbahaya di sana, tetapi TIDAK boleh mendapat endpoint penulis: menimpanya dengan id sekolah lain adalah cara memakai lisensi sekolah itu. `instance_web` wajib untuk Web; `website` opsional dan menolak alamat IP, karena IP jaringan lokal tidak unik antarsekolah dan mewajibkan domain berarti mewajibkan sekolah online. Host yang dicocokkan dibaca dengan aturan yang SAMA dengan `isSameOriginRequest`, supaya proxy yang memalsukan host sekaligus mematahkan pemeriksaan same-origin. Tiga penolakan "pemasangan ini tidak tercantum" sengaja memakai status `device_not_listed` supaya layar aktivasi yang ada menanganinya tanpa cabang baru. Sakelarnya, `KOS_LICENSE_ENFORCED`, dan `KOS_BUILD_DATE` DITANAM saat build lewat `env` di `next.config.ts` (hanya `Dockerfile` yang menyalakannya): sakelar yang dibaca dari `.env` server bisa dimatikan pembeli dengan satu baris. Gerbangnya di SATU tempat, `requireWebPermission`/`requireWebSession` (`server/auth/authorize.ts`), ditambah awal route login dan route bootstrap; daftar izin mode baca-saja (`readOnlyAllows`) wajib sama dengan `read_only_allows`. Status lisensi bisa dibaca tanpa sesi (layar aktivasi harus tampil saat tidak ada yang bisa masuk), tetapi daftar perangkat, kode instance, dan alamatnya hanya dikirim kepada Superadmin. Batasnya: server berjalan di mesin pembeli, jadi tanda tangan mencegah lisensi DIPALSUKAN, bukan mencegah pemeriksaannya dibuang dari kode terkompilasi, dan database yang disalin ikut membawa id-nya; mendeteksi satu lisensi di dua tempat butuh aktivasi online, yang sengaja belum ada.

**Situs publik (`web-public`) ikut dilisensikan, dan tidak pernah memberi tahu publik alasannya.** `web-public` adalah bagian dari produk yang dijual (landing page sekolah, PMB, portal wali) dan melayani database yang sama, jadi ia menilai `app_license` yang sama dengan pemeriksa yang sama: `lib/license/types.ts` dan `lib/server/license.ts` DISALIN dari `web-desktop` lewat `web-public/scripts/sync-shared-lib.ts`, sehingga berkas itu tidak boleh mengimpor apa pun yang hanya ada di `web-desktop` (gateway, RBAC, `initDatabaseSchema`; pembungkus yang melempar `AuthorizationError`, `assertWebLicense`, tinggal di `server/auth/authorize.ts`). Gerbangnya ada di `web-public/src/proxy.ts`, bukan di layout: layout di-cache dan membaca profil sekolah, sedangkan jawaban yang benar untuk situs yang tidak boleh dilayani adalah 503 tanpa konten sekolah, yang hanya bisa dikirim sebelum layout berjalan. Vonisnya tiga (`license-gate.ts`): `terbuka`; `baca-saja` (sewa habis: halaman tetap tampil, `POST /api/pmb/daftar` ditolak di proxy, dan halaman formulirnya membaca header internal `x-kos-lisensi` supaya tidak ada yang mengisi formulir sampai selesai lalu ditolak); `terblokir` (HTML utuh dari `halaman-tidak-tersedia.ts`, 503 + `noindex` + `Retry-After`). Teks yang dilihat publik SENGAJA tidak menyebut lisensi, sewa, atau pembayaran ("Situs ini sedang tidak tersedia", "Pendaftaran online sedang ditutup sementara"): lisensi adalah urusan sekolah dengan penyedia aplikasi, dan alasan lengkapnya tampil di layar masuk aplikasi admin; tesnya menolak kata-kata itu. Header `x-kos-lisensi` kiriman klien selalu dibuang lebih dulu. Situs publik TIDAK PERNAH menulis ke database, termasuk untuk melahirkan `web_instance_id` (`createInstance: false`): tanpa id, lisensi dinilai tidak tercantum sampai aplikasi admin dibuka sekali. Database yang tidak terbaca bukan alasan memblokir (halaman sudah punya pesannya sendiri untuk itu). Bila lisensi dikunci ke alamat, alamat situs publik wajib ikut tercantum di `website`. Build image-nya berbeda dari build Vercel dalam satu hal yang menentukan: `web-public` biasanya MENOLAK dibangun tanpa database karena ia membekukan isi sekolah saat build (ISR), sedangkan image dibangun sekali tanpa database siapa pun. Pada build standalone, `KOS_SELF_HOSTED` ditanam dan `tolakBuildTanpaKonfigurasi` memanggil `connection()`, sehingga semua halaman dirender saat diminta; harganya cache lima menit tidak berlaku (±2 detik per halaman bila databasenya Turso cloud, tidak terasa bila `sqld` ada di mesin yang sama). `KOS_SITE_URL` dibaca saat JALAN dan `sitemap`/`robots` `force-dynamic`, karena `NEXT_PUBLIC_SITE_URL` ditanam saat build dan akan membuat sitemap semua sekolah menunjuk ke alamat yang sama.
