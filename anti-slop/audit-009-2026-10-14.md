# Audit 009: PDF Rekap Nilai dan Kuitansi Fase N2b

Tanggal: 2026-10-14
Cakupan: tombol "Unduh PDF" di tab Rekap Nilai Akhir (`components/nilai/RekapNilai.tsx`) dan di dialog kuitansi (`components/keuangan/PembayaranPanel.tsx`), serta isi kedua PDF (`components/nilai/rekapPdf.ts`, `components/keuangan/kuitansi.ts`). Diperiksa dari kode dan dari isi PDF yang dihasilkan tes; belum dibuka di perangkat.
Mode: antislop setelah selesai (pilihan User untuk sesi ini). User meminta temuan langsung diperbaiki setelah `bun run check`.

Prioritas mengikuti tingkat aturan: Hard Gate = TINGGI, Purpose-Gate = SEDANG, Quality Lock = RENDAH.

## RENDAH

### 1. Dialog kuitansi diam setelah PDF tersimpan (R-27, C-4)
- **Bukti:** `unduhPdf` di dialog kuitansi hanya menampilkan pesan bila gagal. Di Android, dialog SAF tertutup setelah menyimpan dan layar tidak berubah, sehingga petugas tidak tahu apakah berkasnya sudah ada. Tab rekap sudah menampilkan "Berkas PDF tersimpan."
- **Perbaikan:** dialog menampilkan "Berkas PDF tersimpan." (`role="status"`); pesan gagal tetap berwarna merah dengan `role="alert"`. Menutup dialog simpan tetap dianggap pembatalan dan tidak memunculkan pesan.

## Lolos

- **R-02:** tidak ada tanda pisah panjang pada teks baru, termasuk isi PDF (sel kosong ditulis "-").
- **R-17/R-38:** isi PDF dibangun dari data yang sama dengan layar; PDF rekap mencantumkan waktu hitung dan "belum dibekukan".
- **R-26:** kedua tombol menjalankan aksi nyata; pembatalan dialog simpan dibedakan dari kegagalan.
- **R-27:** pembuatan PDF yang gagal menampilkan pesannya; peringatan nilai kosong berlaku untuk PDF maupun Excel, lengkap dengan "Ya, lanjutkan" dan "Jangan ekspor".
- **Offline:** pustaka PDF dibundel dan dimuat hanya saat dibutuhkan; logo kop hanya dipakai bila berupa data URL, jadi tidak ada unduhan gambar.
