# Kerjakan Fitur Lintas Platform

Aturan proyek ada di `CLAUDE.md` dan `.agents/skills/absensi-sppg-rules/references/`; bila
bertentangan dengan skill ini, `CLAUDE.md` menang. Tiga fakta penentu: setiap aturan bisnis dieja
dua kali (TS untuk Web, Rust untuk Desktop/Mobile) dan diuji dengan vektor yang sama;
`web-desktop` kanonik, Mobile sebagian besar salinan skrip; UI hanya lewat `src/lib/gateways/*.ts`.

## A. Pahami (baca saja)

1. Tafsirkan rujukan seperti "poin 1"; sebut tafsiran di kalimat pertama bila ambigu, tanpa
   berhenti untuk bertanya bila koreksinya murah.
2. Cek `MEMORY.md`: keputusan yang sudah ditutup tidak ditawarkan ulang.
3. Bila brief sudah menyebut berkas/fungsi, baca itu langsung. Selain itu telusuri alurnya di kedua
   bahasa: service TS + route, fungsi Rust + command, gateway, dan setiap layar yang membaca atau
   menulis data yang sama (Grep nama field).
4. Bandingkan kunci JSON UI ↔ Rust secara harfiah (Tauri tidak mengonversi kunci di dalam objek) dan
   periksa setiap pembangun draft yang menyimpan objek yang sama.

## B. Rencana, lalu berhenti

5. Tulis rencana: kondisi sekarang, pendekatan dan alasannya, alternatif yang ditolak, batasan bagi
   pengguna, bug lama yang ikut ditemukan, dan keputusan berhuruf (A, B, …) masing-masing dengan
   rekomendasi.
6. Berhenti sampai user menjawab. Jawaban per huruf = final. Pengecualian: user berkata "langsung
   saja" atau rencananya sudah disetujui (misalnya di PRD).

## C. Implementasi (urutan ini meminimalkan kerja ulang)

7. Konstanta dan tipe dulu (`validations/*.ts` ↔ `pub const` Rust, saling menunjuk); field baru
   wajib (bukan `?:`) supaya `tsc` menunjuk pembangun draft yang lupa.
8. Skema hanya bila perlu, semua lapis sekaligus: `storage.rs` (Desktop DAN Mobile, tidak disalin
   skrip), `turso.rs`, `db-schema.ts`/`db-migrations.ts`, `ensure_column` + `ALTER TABLE`, versi
   (`CURRENT_SCHEMA_VERSION`, `CLIENT_SCHEMA_VERSION`, seed `schema_migration`, tes RBAC),
   `REQUIRED_TABLE_COUNT`. Setting sederhana = kunci `setting_gex_system`, bawaan MATI.
9. Logika Rust di `src-tauri/src/desktop/`; modul baru = `pub mod` di kedua `mod.rs` + `filesToSync`.
   Fungsi murni dipisah dari I/O.
10. Command baru: kedua `lib.rs`, `build.rs`, `capabilities/default.json`,
    `permissions/autogenerated/<command>.toml`; `///` sebelum `#[tauri::command]`; izin diperiksa
    lebih dulu.
11. TS: service + route (`assertSameOriginMutation`, `requireWebPermission`, Zod `.strict()`), lalu
    gateway satu fungsi dua cabang, lalu UI (label setiap kontrol, `isSubmittingRef`). Komponen
    identik byte di kedua workspace masuk `filesToCopy`.
12. Crate yang dipakai kode aplikasi ada di `[dependencies]`, bukan hanya dev.
13. Tes: vektor kembar Rust (`mod tests`) ↔ TS (`*.test.ts`) dengan masukan dan hasil sama; satu tes
    integrasi TS dengan database memori (`createClient({ url: "file::memory:" })`, satu klien per
    berkas, `mock.module("server-only", () => ({}))`).
14. Dokumentasi: invarian arsitektur baru ditulis di `references/` yang sesuai; `CLAUDE.md` paling
    banyak satu baris tabel.

## D. Sinkronisasi dan verifikasi (per berkas, tanpa membanjiri konteks)

15. Dari `mobile/`: `bun run scripts/sync-rust-modules.ts` dan `bun run scripts/sync-frontend-lib.ts`.
    Ulangi setelah formatter. Jalankan sebelum tes literal yang membaca salinan Mobile.
16. Format hanya berkas yang diubah: `bunx biome check --write <berkas>`; `rustfmt` hanya berkas
    Rust BARU.
17. Verifikasi yang Claude jalankan: `bunx tsc --noEmit` per workspace, `bun test <berkas>`,
    `cargo test <nama>` dengan output ke scratchpad (baca baris `test result`/`FAILED` saja), dan
    audit yang relevan (`bun run audit:contract`, `audit:schema`, …) dengan output ke berkas.
18. Claude TIDAK menjalankan `bun run check`, `check:quick`, suite Rust penuh, antislop, atau
    commit. Akhiri dengan meminta pemilik menjalankan `jalankan-antislop` lalu `jalankan-check`.

## Dilarang

- Kode sebelum rencana disetujui (kecuali B.6).
- Menyunting salinan Mobile sebagai satu-satunya perbaikan.
- Melonggarkan audit; `UNIQUE` selain PK di tabel tersinkron; menormalkan enum asing.
- Menyatakan "terverifikasi penuh" tanpa `HASIL.md` segar dari pemilik.

## Kegagalan yang sering terjadi

1. Kunci camelCase/snake_case tidak cocok antara UI dan Rust: semua "berhasil" tetapi tersimpan
   bawaan. Tes Rust memakai payload persis seperti yang dikirim gateway.
2. Pembangun draft lupa field baru sehingga pilihan user tertimpa; field wajib di tipe TS.
3. Berkas Mobile yang tidak disalin skrip (`storage.rs`, `lib.rs`, `build.rs`, capabilities)
   terlewat.
4. Libsql di Bun Windows segfault bila satu berkas tes membuat klien baru setelah menutup klien lain:
   satu klien per berkas.
5. Heredoc yang memuat tanda kutip tunggal gagal di shell: tulis skrip panjang dengan Write.
